## Negative results

Codes / families that a technician may encounter, that we searched for, and that we could **NOT** verify from a source fetched in this session. Nothing here was added to a series block.

### 1. CPS1000EILCD / CPS1200EILCD / CPS2200EILCD — "Fault Code Table" (page 15) — NOT VERIFIED, codes withheld
CyberPower Pakistan actively markets the **CPS1200EILCD** (official PK product page: https://www.cyberpower.com/pk/en/product/sku/cps1200eilcd), so this table matters commercially. However:
- The manual PDF itself could not be obtained. `dl4jz3rbrsfum.cloudfront.net` returned **HTTP 403** for every `*CPS*EILCD*` filename tried; the US site search for "CPS1200EILCD" returns "0 results"; reichelt-style CDN guesses returned 404.
- The only text available is **OCR-degraded third-party page previews**: https://www.manualslib.com/manual/2431427/Cyber-Power-Cps1000eilcd.html and https://manualshive.com/en/manual/cyber-power/cps1000eilcd/2701459.
- Those previews render the table as: `... e Alarm | A64 Overload | Rapid beeping every 1/2 second | E07 Output Voltage High | Constant tone | E09 Output Short | E14 Overload Fault | E18 Fan Fail | E13 Over Charge | E25 Output Unbalance | Constant tone ...`
- Six code strings (**E07, E09, E13, E14, E18, E25**) are legible and are corroborated by both previews, but the **Overload row's code is unreadable** (renders as "A64"/"e Alarm" — almost certainly an OCR mangling, and "A64"/"E64" must NOT be guessed). The rows are also presented out of table order by both sites, so the code→event pairing cannot be trusted at 1:1 even where the text is legible.
- **Decision: withheld.** No primary source was fetched. Recorded here so the gap is explicit and can be filled by fetching the actual manual from a CyberPower regional site that serves it.

### 2. SMP1400EILCD / SMP2000EILCD / SMP2500EILCD / SMP3500EILCD ("Static UPS") — fault codes E8–E14 — NOT VERIFIED, withheld
Search previews (https://usersmanualguide.com/cyberpower/ups/smp1400eilcd/user-manual/1u4bf) show a documented troubleshooting table with: **E8 Output Short**, **E9 Battery high**, **E10 Battery Low**, **E11 Over Temperature**, **E12 Overload in line Mode**, **E13 Overload in Battery Mode**, **E14 Fan fail** — each with numbered remedies. But:
- No primary PDF was retrieved (CyberPower CDN 403, reichelt guess 404).
- Only **one** host exposes the content, and its OCR is degraded (`Fault code E1 1`, `E1 2`, `E1 3`).
- Note the collision: this family's **E11 = Over Temperature** and **E13 = Overload in Battery Mode**, which is the *exact opposite* of SERIES 1/2/8 (E11 = Battery Overvoltage, E13 not used). That is a dangerous trap, so the rows are withheld rather than published on one degraded source.
- **Also:** the SMP units are marketed as "Static UPS" and are not confirmed as being in CyberPower's Pakistan range.

### 3. OLS1000ECp — 9-LED "Warning and Fault Code" table (17 numbered items) — NOT VERIFIED, withheld
Search preview (https://usersmanualguide.com/cyberpower/ups/ols1000ecp/user-manual/1djx9) shows a distinct table: items 1 Over Load Warning, 2 BUS Start Fail, 3 BUS Volt High, 4 BUS Volt Low, 5 BUS Unbalance, 6 BUS Start Fail (duplicate of 2 in the source), 7 INV Volt High, 8 INV Volt Low, 9 INV Short, 10 BAT Volt High, 11 Over Charge, 12 BAT Capacity Low, 13 Over Temperature, 14 Over Load Fault, 15 High Temperature, 16 BAT Bad or Disconnected, 17 Fan Fail — with 9-LED states and alarm sounds. **No primary PDF retrieved; single host; OCR degraded (the LED dots are lost).** The item numbering itself is internally inconsistent (2 and 6 both "BUS Start Fail"), which is a further reason not to publish it. ### 4. CPS1200EO12LCD / CPS1200EOH12SC and "CPSPV33000ETL" — A00–A07 / E50–E54 codes — NOT VERIFIED, withheld

## Conflicts / caveats

Real, documented conflicts between CyberPower's own sources. Each of these means the KB must key on **family**, never on the bare code string.

**C1 — Same `E` string, different meaning, across CyberPower families.**
- SERIES 1/2/8: `E21` = **Battery Output Short Fault** / **Output Short**; `E22` = **Battery Mode or AC/Utility Power Mode Overload Fault** / **Overload**; `E11` = **Battery Overvoltage**; `E01` = **Charger Fault – Overcharge**; `E02` = **Charger Fault – No Charge**.
- SERIES 7 (VP700/1000/1200/1600E(I)LCD): same strings `E01`, `E02`, `E21`, `E22` with the same meanings, but **shortened wording** ("E21 : Output short.", "E22 : Over load.") and **no `E11` at all**. → A technician expecting 5 codes on a VP unit will look for an E11 that this hardware never produces.

**C2 — `F01`–`F04` is CyberPower's *other* namespace, and it collides with APC.**
- SERIES 3 (EPFCLCD): `F01` = Overload, `F02` = Battery Output Short, `F03` = Charger Fault, `F04` = Internal Fault.
- **APC Back-UPS** (quarantined): `F01` = On-Battery Overload, `F02` = On-Battery Output Short, `F03` = On-Battery Xcap Overload, `F04` = Clamp Short, continuing to F09.
- The first two are deceptively close, and F03/F04 diverge completely. **A CyberPower EPFCLCD and an APC Back-UPS in the same PK installation must never share an F-code lookup.**

**C3 — `E11` is not a stable concept across CyberPower.**
- SERIES 1/2/8 (CP/LX LCD families): `E11` = **Battery Overvoltage** (a charger/battery protection trip).
- **SMP series** (unverified, withheld — see NEGATIVE 2): `E11` = **Over Temperature**. `E13` = **Overload in Battery Mode**, which on the CP families is not used at all and whose nearest equivalent is `E22`.
- The same string E11 therefore covers battery overvoltage on one CyberPower line and overheating on another. This is why the SMP rows are withheld rather than published.

**C4 — `E01` is present on some models of the same platform and absent on others.**
- LX1100G3 / LX1325GU3 / LX1500GU3 manual: FAULT list = `E01, E02, E11, E21, E22` (5 codes).
- CP1350AVRLCD3 / CP1500AVRLCD3 manual (same shortened "Output Short / Overload" wording): FAULT list = `E02, E11, E21, E22` (**4 codes — E01 removed**).
- Also observed: a CP1500PFCLCD-family manual revision (https://images.salsify.com/image/upload/s--F045jzYE--/364392f67932a1d94b0f830be5601f4ab60ab749.pdf) that lists `E01, E02, E11, E21, E22` with E21 as "Output Short Fault" and E22 as "Overload", while a different CP1500PFCLCD revision (https://dl4jz3rbrsfum.cloudfront.net/documents/CyberPower_UM_CP1500PFCLCD.pdf) says "Battery Output Short Fault"/"Battery Mode or AC/Utility Power Mode Overload Fault". → **Same model number, two manual revisions, different code sets and different text.** Model number alone is not a safe key; firmware/hardware revision is.

**C5 — The same code text is not a stable description of the same fault across revisions.**
- SERIES 2/8 manual wording pairs: `E01 : Charger fault (Over Charge).` / `E02 : Charger fault (No Charge)` / `E11 : Battery Fault` / `E21 : Output short.` / `E22 : Over load.` — this is the wording used on the **Function Setup Guide "Last Fault Reason" page** (https://dl4jz3rbrsfum.cloudfront.net/documents/CyberPower_FG_CP1500AVRLCDTAA.pdf), whereas the **user manual's FAULT icon** for the same models says `E11: Battery Overvoltage` and `E21: Battery Output Short Fault`.
- → **Within one product, CyberPower's own two documents gloss `E11` two different ways** ("Battery Overvoltage" vs the broader "Battery Fault") and `E21` two different ways ("Output short" vs "Battery Output Short Fault"). The KB should use the FAULT-icon wording as canonical and record the Function Setup Guide wording as an alias.

**C6 — Identical-looking code pairs mean different things on the OLS series vs the CPS/ECO series.**
- OLS (SERIES 5): `31` = High Output Voltage, `34` = Fan Error, `22` = Output Overload, `40`–`44` = Bus Fault.
- CPS1000EILCD (withheld, NEGATIVE 1): `E07` = Output Voltage High, `E18` = Fan Fail, `E14` = Overload Fault, `E25` = Output Unbalance.
- Same fault concepts, totally different numbering. And **OLS `54` = Line Abnormal** whereas the E-family `E54` (CPS1200EOH12SC) is a different product entirely. → Never key an OLS user to an E-code.

**C7 — "Last Fault Reason" is a separate display surface with its own list.**
- SERIES 2's Function Setup Guide exposes a `Last Fault Reason` page that "will only show the error code for last fault reason" — i.e. a *retrospective* record, not a live alarm. The same page on SERIES 7 lists only 4 codes. A technician reading the LCD in setup mode and a technician reading the live FAULT icon may legitimately see different lists for the same unit. Flag this in the UI so "last fault" is not presented as a current fault.

**C8 — Third-party Q&A contradicts the vendor manual (documented false lead).**
- https://www.manua.ls/cyberpower/cp1500pfclcd/manual and https://www.manualslib.com/answers/4499445/cyberpower-cp1300epfclcd-unexpected-shutdown-troubleshooting.html both present F01–F04 as "UPS Fault Codes". For a **CP1500PFCLCD** this is wrong (that model is E-coded); the CP1300EPFCLCD page is right about its own model but the manua.ls page mis-attributes F-codes to the PFCLCD. If a KB is built from search snippets rather than manuals, this specific error is very likely to appear.

1. **CyberPower's CDN (`dl4jz3rbrsfum.cloudfront.net`) returns HTTP 403 for any filename not already known** — the official `resources/<sku>-um/` pages are JavaScript-driven and the real PDF URL is not in the page HTML. This blocks systematic discovery of official manuals (blocked: all `CPS*EILCD*`, `SMP*EILCD*`, `OLS1000ECp*` attempts).
2. **The US site (`cyberpowersystems.com`) has 0 results for the PK-relevant SKU CPS1200EILCD** — the CPS/ECO home-UPS line that Pakistan actually sells lives only on `cyberpower.com/pk` / `cyberpower.com/global`, and its manuals are not indexed by any search engine I could reach.
3. **Consequently the CPS1000EILCD/1200EILCD/2200EILCD "Fault Code Table" (page 15) could not be read from a primary source**, and the Overload row's code is unreadable in every OCR copy. This is the most commercially relevant gap, because CPS1200EILCD is a headline PK product. → See NEGATIVE 1.
4. **SMP series and OLS1000ECp tables exist but rest on single degraded third-party sources** → withheld (NEGATIVE 2, 3).
5. **No consolidated official code table exists** → the KB cannot offer one authoritative page; it must be family-scoped, and CONFLICTS C1–C8 mean the code string alone is never a safe lookup key.
6. **CyberPower has revised its own manuals within the same model number** (C4/C5), so a code set can be incomplete or differently worded depending on the manual revision the technician is holding. The KB should record the manual revision (K01-xxxxxx-xx) alongside every code.

**Official table: NO.** No single brand-level official error/fault-code table is published by CyberPower. Codes exist only inside individual per-family user manuals and Function Setup Guides (official examples: https://www.cyberpowersystems.com/resources/cp1500pfclcd-um/ and the Function Setup Guide on CyberPower's own CDN). The strongest single official table is the **OLS series "EVENT CODE LIST" + "TROUBLESHOOTING"** (29 codes) inside that model's official manual.

**PK presence: YES.** Evidence: (a) dedicated official Pakistan region site `https://www.cyberpower.com/pk` with its own Where to Buy / partner search (`https://www.cyberpower.com/pk/en/wheretobuy`, locale "pk - en"); (b) authorised distributor **CyberPower Pakistan / Electronic Office Products**, 305 Clifton Center, Kheyaban-e-Roomi, Clifton Block 5, Karachi, +92-21-35873459 — "CyberPower Pakistan began it's journey in 2009, as CyberPower's exclusive and authorized distributor across Pakistan" (https://www.citysearch.pk/cyberpower-pakistan-karachi); (c) EOP's own company page listing "CyberPower Systems (UPS, Emergency Power Systems & Solar Solutions)" among the multinationals it represents in Pakistan (https://www.linkedin.com/company/electronics-office-products); (d) PK-market SKU confirmation, including the CPS1200EILCD on CyberPower's own PK store page and grey-import listings of CP1500PFCLCD / ST425 / ST625U at Pakistani retailers (https://nifdo.com/cyberpower). Practical note for the KB: the models actually documented in this file (CP/PF, CP AVR, EPFCLCD, UT, OLS, VP, LX) plus the withheld CPS line are all part of the PK-relevant range, whereas APC/Eaton-style F-code lookups are a live confusion risk in the same installations.
