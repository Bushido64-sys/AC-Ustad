# Solis (`solis`) — sources

Category: **inverter** · Registered: **2026-09-26** · Codes: **89** across **8** model-scoped series

Official: https://www.solisinverters.com

Ginlong Technologies brand, very common in Pakistan on-grid residential and small commercial. S5-GR1P single-phase string is the volume seller here; S5-EH1P-L hybrid is widely installed with 48V lithium.

## Brand recon

- **Brand**: Solis (Ginlong Technologies), China. Corporate site https://www.solisinverters.com — brand key only.
- **Corporate / support domains seen**: `solisinverters.com`, `solis-service.solisinverters.com` (official Freshdesk support portal), regional sites `solisinverters.com.au`, `ginlong.com` (parent Ginlong uploads folder still hosts manuals).
- **Product families relevant to this KB**:
  - On-grid string, single phase: **S5-GR1P** (2.5–12 kW), **S5-GR1P-M** mini (0.7–3.6 kW), newer **S6-GR1P**.
  - On-grid string, three phase: **S5-GR3P** (3–13 kW low voltage / 20–60 kW), **S5-GC** (25–50 kV / 50–70 kW commercial), **S6-GR3P**.
  - Hybrid (PV + battery): **S5-EH1P / S5-EH1P-L** (single phase 3–6 kW + battery), **S6-EH1P**, **S6-EH3P** (three phase 3–10 kW and 12–20 kW), **RHI-(3-6)K-48ES** / RHI-5G (single phase hybrid with 48 V battery), **S5-ES / S6-ES** storage.
  - Meter / EPM: **EPM** (external power meter used for export management, appears as an external EPM on S6-EH3P).
- **Code format — IMPORTANT, three distinct dialects, kept in separate series blocks**:
  1. **On-grid string inverters (S5-GR / S5-GC / S6-GR)**: LCD prints a *text* alarm name, e.g. `OV-G-V01/02/03/04`, `UN-G-V01/02`, `OV-DC01/02/03/04`, `PV ISO-PRO 01/02`, `ILeak-PRO 01/02/03/04`, `OV-TEM`, `INI-FAULT`, `DSP-B-FAULT`, `12Power-FAULT`, `DCinj-FAULT`, `Relay Chk-FAIL`, `GRID-INTF01/02`, `IGFOL-F`, `IG-AD`. Same names, no hex shown on grid models.
  2. **Hybrid / storage inverters (S5-EH1P, S6-EH1P, S6-EH3P, RHI)**: LCD prints *text name + hex code + data field*, e.g. `OV-TEM (1032 DATA:0000)`, `INI-FAULT (1031 DATA:0000)`, `ARC-FAULT (1041 DATA:0000)`, `IGBT-OV-I (1048 DATA:0000)`, `12Power-FAULT (1038 DATA:0000)`, `DCInj-FAULT (1037 DATA:0000)`.
  3. **S6-EH3P (and S6-EH1P) new-DSP platform**: LCD prints a *numeric code only* in decimal, e.g. `1037`, `1065` (HeartbeatLose), plus an internal `Alarm Grade` (e.g. `EMGR`) — a different numbering space from the 1xxx/2xxx hex names above. Do not merge with dialect 2.
  - Therefore: **the same number is NOT the same code across platforms** (e.g. `1030` is GRID-INTF on the S5 on-grid hex map but S6-EH3P uses 1030 differently — see CONFLICTS). Tables are kept separate.
- **Official alarm library (verified 2026-09-26)** — Solis publishes a single master table, `Alarm Code Maintenance_20260204.xlsx` (830 data rows, attached to the official KB article "Full Alarm Code Maintenance Overview"). Its own `Device Type` column is the authority for scoping:
  - `Only Grid Connection` (175 rows) → on-grid string inverters (S5-GR1P / S5-GR3P / S5-GC / S6-GR). Codes `10xx` (grid) and `20xx` (AFCI / EPM / DRM / G100 meter).
  - `Only Energy Storage` (126 rows) → hybrid / storage inverters (S5-EH1P, S6-EH1P, S6-EH3P, RHI). Battery rows `1053/1054/1055/105C/1070/107C/107D/107E/107F/105B`, backup rows `1056/1057/1022/2048`, parallel rows `1060-106C`.
  - `ALL` (299 rows), `Battery` (158), `HUB` (57), `AC` (8), `FPS` (7) — shared / other devices.
  - The `Fault Grade` column maps to app severity: **Tip** = monitor, **General** = inspect, **Emergency** = act now. This is why the blocks below are scoped by device and never merged.
  - Column split that proves the "same number, different meaning" rule: `Fault Status Code(Grid Connection)` vs `Fault Status Code(Energy Storage)` vs `Fault Status Code (Battery)` are three different numeric spaces stored against the same `Fault Code` cell.
- **Pakistan presence**: Solis has an official regional presence in Pakistan (Ginlong Solis Pakistan / Solis Pakistan, with local distributors selling S5-GR1P and hybrid S5-EH1P-L). Treat as a mainstream residential/on-grid brand in the PK market; no NEPRA-specific Solis fault-code list found. Grid standard in PK is generally set to a user-defined / generic EN50438 or PK-GRECO style limit via `Advanced Settings -> Password 0010 -> Select Standard`.
- **No other brand's codes may be mixed in** — see `## QUARANTINE`.

The Bolido Solar page (source 13) is a distributor of many brands. None of those brands' codes appear anywhere above.
- **easymanua.ls / manualspro / manualslib / scribd AI or crowd-sourced Q&A text** — quarantined as evidence. Sources 11 and 12 in the SOURCE TABLE were originally used for the hybrid `NAME (10xx DATA:0000)` format; that format is now confirmed from Solis's own manuals (sources 20, 23) and the official KB, so the mirror Q&A content is no longer load-bearing.
- **The master table's reserved / placeholder rows** — `13880`-`13986`, `15F90`-`15FF2`, `16007`, `B10003`-`B1000B` (mostly blank descriptions), `11170 Reserved`, `15FB8` whose description is literally `1`, and `186C2/186C3/186C8/186C9 reserved`. Not turned into entries; a technician must never be shown a code whose description in the manufacturer's own table is `--` or `reserved`.
- **State codes that are not faults** and are therefore excluded from the fault entries: `0 Waiting`, `1 OpenRun`, `2 SoftRun`, `3 Generating`, `1004 Grid Off`, `0000/2 Waiting01`, `F018 DSP_Comm Alarm`, `F019 0000_BoostFail`, `F034 CALI_ZERO_SHIFT`, `13880 Reserved`. The harmless subset that IS useful to a technician is kept as `isFault: false` rows instead (`LmtByEPM`, `LmtByVg`, `LmtByTemp`, `StandbySynoch`, `GridToLoad`, and the LED rows).
- **`Alarm Grade` strings** (`EMGR`, `Hint`, `General`, `Tip`, `Emergency`) are Solis's own grading vocabulary, not other-brand codes, and are quoted only as they appear in the official table / S6 manuals.
- **Two brands of Solis lithium pack (Pylontech, Dyness) appear in the sources.** Their fault codes are NOT included. Only Solis-side codes (`Batt_Comm_FAIL` 2012, `BatName-FAIL` 2016, `CAN Fail`, `NO-Battery`) are recorded, because those are what the Solis inverter prints.

## Conflicts / caveats

1. **`1030` — grid interference vs AC hardware overcurrent.** On-grid (S5-GR1P / S5-GR3P / S5-GC) the master table and the manuals give `1030 = GRID-INTF. = Grid interference` (waveform distortion). On hybrid (S5-EH1P-L / S6-EH1P / S6-EH3P) the same hex prints as `GRID-INTF. (1030 DATA:0000) = AC hardware overcurrent (abc phase)`. Handled by keeping SERIES 1/2/3 and SERIES 4/6/7 apart; SERIES 4 and SERIES 7 both carry an explicit conflict note.
2. **`1038` — 12 V supply fault vs 12 V undervoltage.** On-grid manuals: `12Power-FAULT / 12V power supply fault`. Hybrid manual Table 8.1: `12Power-FAULT (1038 DATA:0000) / 12V undervoltage failure`. Master table: storage scope calls the same code `UN-12VPower`. Different root cause, different fix (on-grid = failed SMPS; hybrid = earth leakage pulling the rail down).
3. **`1048` — IGBT overcurrent vs third overvoltage window. THIS IS THE MOST DANGEROUS ONE.** The hybrid manuals (S5-EH1P-L, S6-EH1P, S6-EH3P) print `IGBT-OV-I (1048 DATA:0000) = IGBT overcurrent`, and SERIES 1 already carries `1048` as an alias of the on-grid `IGBT-OV-I` text name. But Solis's own master alarm table assigns `1048` to `OV03-G-V` (grid overvoltage, third window) on BOTH the grid and the energy-storage scope, and puts "IGBT Over Current" only as an unnamed `186BD` row. The manual's `(1048 DATA:0000)` pairing is therefore not corroborated by the manufacturer's master library. **Recommendation: do not let a technician enter 1048 expecting an IGBT fault; read the full message text.** SERIES 1's `1048` alias is left in place but flagged here.
4. **`OV-Vbatt` / `UN-Vbatt` descriptions are swapped between manuals.** `S5-EH1P(3-6)K-L(-BE) EUR` and `S6-EH3P(29.9-50)K-H` both say `OV-Vbatt = Battery undervoltage` and `UN-Vbatt = Battery overvoltage`. `S6-EH1P(3-6)K-L-AU` says the exact opposite. **Always measure the pack before acting** — this is stated in both SERIES 7 entries.
5. **Parallel / 3-phase communication codes `1060`-`1063` have DIFFERENT names on the two device scopes.** Grid scope: `1060 SlaveLoseErr`, `1061 MasterLoseErr`, `1062 SlavePrd-Err`, `1063 MasterPrd-Err`. Energy-storage scope: `1060 SlaveSyncLose`, `1061 MasterSyncLose`, `1062 SlaveSyncErr`, `1063 MasterSyncErr`. `106B` is `CAN BUS LOSE` (grid) vs `CAN-BUS-Lose` (storage); `106C` is `3P_CreateFail` (grid) vs `3P_CreateFaACil` (storage). `1064 Addr-Conflict`, `1065 HeartbeatLose`, `1066 DCanErr`, `1067 MulMasterErr`, `1068 ModeConflict` are the same on both.
6. **`1011` spelling differs by scope.** Grid: `UN-G-V` / `UN-G-V01` / `UN-G-V02`. Energy storage: `UV-G-V`, `UV-G-V01`, `UN-G-V02`. The master table itself contains both spellings for the same code.
7. **Severity grading of identical codes differs by scope.** `1010`/`1011`/`1012`/`1013` are `Tip` on the grid scope and `General` on the energy-storage scope. `1032 OV-TEM` is `General` on grid and `Emergency` on storage. A code's severity in this KB is therefore model-scoped, not a property of the number.
8. **`1032 OV-TEM` trip temperature is quoted two ways.** Solis's official article says the alarm appears when the inverter detects ambient above `60 °C / 140 °F`; the Aussie Solar retailer table says `Internal temp over limit (90 °C / 115 °C)`. The official figure is used. Both SERIES 1/2/3 entries use 60 °C as the practical check.
9. **`OV-TEM` remedy differs by scope.** Grid: reduce ambient, restart after 15 minutes, then factory service. Storage: check that the installation position meets the manual, ensure ventilation, restart after 15 minutes, then customer service. A hybrid unit is derating on the backup/LLC side as well, so an on-grid OV-TEM fix can miss the real cause.
10. **Same name, three different codes for DC overvoltage on the storage scope.** `1020 OV-DC`, `1801 OV-DC05..OV-DC10` and `1800 OV-DC-I` all exist; the manual Table 8.1 only prints `1020`. SERIES 4/6/7 use `1020` only.
11. **Backup overload has two codes.** `1057 Overload` (storage) and `2030 BKAC Overload` (ALL scope, grid 0202). The RHI manual calls the same symptom `Over-Load`. SERIES 4 and SERIES 5 both use the name `Over-Load` with the manual's own wording, since that is what the LCD shows.
12. **Source 8 (solar.bg) is dead** and was replaced. The S5-GC rows in SERIES 3 are now cited to the helius.com.ua EUR V1.3 mirror plus the official Solis Australia V1.0 manual; both were fetched and agree on the AFCI rows.
13. **`PHASE-FAULT` naming is inconsistent across sources.** Master table: grid `101A PHASE-FAULT`, storage `101A Phase-Fault`; the Aussie Solar retailer table also says `101A`. SERIES 2's note records that the retailer's `101A` for `PHASE-FAULT` is not on the Solis KB list — that remains true, but the official master table has since been published and DOES carry `101A PHASE-FAULT`, so the alias is now corroborated. The S5-GR3P manual's own `G-PHASE` row is the text name for `1016`.

- **Official fault table available: YES.** Solis publishes a single authoritative, device-scoped alarm table (`Alarm Code Maintenance_20260204.xlsx`, 830 rows, file dated 2026-02-04) plus ~20 per-code KB articles. Every hex code in SERIES 3-8 is taken from that table or from an official Solis manual, and the table's own `Device Type` column is what justifies the series split. This is the strongest source position of any brand researched so far.
- **PK presence: YES.** Solis (Ginlong) is a mainstream PK brand with an official regional presence and local distributors selling S5-GR1P on-grid and S5-EH1P-L / RHI-48ES hybrids, plus 3-phase S5-GR3P and S5-GC for commercial. Practical consequence for this KB: PK sites are almost always set to a user-defined or EN50438-type limit via `Advanced Settings > Password 0010 > Select Standard`, so the OV-G-V / UN-G-V / OV-G-F / UN-G-F entries in SERIES 1-4 are the codes a PK technician will see most often. No NEPRA/DISCO-published Solis code list was found.
- **Blockers:**
  1. `solar.bg` (previous source 8) and `ginlong.com/uploads` (HTTP 500) are unusable as manual paths; all S5-GC and hybrid manuals had to come from mirrors or the official regional sites (`solisinverters.com`, `solisinverters.au`). Mirror dependence is a durability risk for the SOURCE TABLE.
  2. Solis publishes **no per-model fault table** — the master library is scoped by device class ("Only Grid Connection" / "Only Energy Storage"), so model-level attribution for S6-GR1P, S6-GC(80-125)K, S5-GC(50-60)K, S6-EA1P, PrimePower and EverCore is not possible from what is published. Those models are therefore absent rather than guessed.
  3. The master table's `Treatment Suggestions` are one-line and mostly end in "contact customer service"; every entry above therefore expands them with concrete meter and tool steps taken from the matching official per-code article, the manual's own Table 8.1/9.1 solution column, or the official KB procedure. Where a solution could only be sourced from a retailer, `confidence` was dropped and a `notes` object added.
  4. The manual's `(1048 DATA:0000) = IGBT-OV-I` pairing contradicts Solis's own master table (see CONFLICTS 3). This is unresolved at source level and is the single most likely source of a mis-dispatch in this KB.
  5. Roughly 500 of the 830 master-table rows (Battery, HUB, AC, FPS, SolisCloud-internal `186xxx`, reserved `1388x`/`15F9x`) were parsed but not transcribed; a battery or HUB series would need a separate pass and a separate brand decision about pack-vendor codes.
  6. No PK grid-code value could be verified — only the menu path.
